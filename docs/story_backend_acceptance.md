# Full-story backend acceptance (not yet production approval)

Full-story generation and semantic validation default to unavailable. Ordinary dialogue is unchanged. A method or model name alone is not a whole-story safety capability.

A trusted internal deployment bootstrap must separately construct `StoryContextReceipt` and `StoryBackendContract` for the generator and validator, attach them through each provider's `story_backend_contract` constructor argument, and await `contract.refresh()` before exposing capability. No public event, generated JSON, or child/profile field can supply this receipt. No production receipt or automatic approval is supplied here. The bootstrap is configured by an explicit operator-local receipt file, not an unverified boolean.

Each receipt binds exact loopback HTTP endpoint, model name and digest, server version, llamacpp runner, expiration, accepted context ceiling (4096–32768), template reserve (256–4096), and verified truncate=false/shift=false behavior. Mini-validator capacity is independent of generator capacity: its ordinary 1024 context is not its accepted story ceiling. Context/model/backend changes or expiry invalidate capability; metadata is checked before and after each story request via bounded GET /api/version and /api/ps, without story/profile data. Unloaded models are unavailable; no automatic loading or heavy acceptance probe occurs. Redirects are refused. Pre/post metadata cannot prove the absence of an adversarial replacement between checks; the local backend is a trusted deployment component.

Acceptance must record pinned backend source/protocol evidence for rejecting input overflow with truncate=false and preventing context shifting with shift=false. Both generation and validation additionally require a clean `done=true, done_reason=stop` response; missing terminal or length exhaustion rejects the result before synthesis. `prompt_eval_count` is not proof that original text was retained. Source references: https://github.com/ollama/ollama/blob/v0.40.11/api/types.go and https://github.com/ollama/ollama/blob/v0.40.11/llm/llama_server.go . Review the deployed tagged runner path, not only request fields.

The per-call context reservation rounds UTF-8 message bytes plus accepted template reserve plus output budget to 256, bounded by the receipt ceiling. This is a resource estimate, not a general bytes-to-tokens theorem or semantic quality guarantee. Underestimation must be rejected by the verified no-truncation backend; missing or exhausted terminal responses also fail closed. No tokenizer-calibration attestation is claimed. Oversized requests fail before metadata or model I/O. No blanket 32k allocation and no shared provider mutation occurs. Output reservation is 6000 tokens for generation, 96 for the semantic decision. The external JSON has four plot sections, not a duplicate text field; raw JSON is bounded at 8000 characters and derived body at 6000, so metadata/escaping may further restrict feasible bodies.

Required physical acceptance remains: real complete-story quality, child-safety performance, measured age-specific PCM duration, actual output sample rate, latency/deadlines, RSS and GPU VRAM under ordinary dialogue/story transitions. Ollama shift is a runner launch setting: a story shift=false request may reload a warm default shift=true runner, and following dialogue may reload it again; context resizing may also reload. These tests do not establish a 60-second generation SLA or near-live availability. Do not silently change global dialogue options to avoid that cost.

One story job is admitted at a time; its full private PCM remains in RAM for pause/resume and is cleared on lifecycle cancellation. The code upper guard of 192000 samples/s and 150 seconds permits 28.8 million Python float samples, with substantial tuple/float and temporary-copy overhead. Synthetic low-rate tests are not a performance or OOM guarantee. Measure the configured real RVC output rate and peak allocation before accepting deployment. Native inference cancellation is fencing, not guaranteed immediate computation stop or memory zeroization. No persistent private audio or shared TTS text cache is permitted.

Read-only deployment observations report Ollama 0.40.11 with llamacpp for both Qwen3 models. Pinned source tracing supports input-overflow HTTP 400 and context-exhaustion length termination; this is protocol evidence, not a runtime overflow probe or verification of installed binary provenance/custom builds. No accepted production receipt was created by these code tests.

## Operator bootstrap

Set `MISHKA_STORY_BACKEND_RECEIPT_PATH` to an absolute regular local JSON file after separate approval. Default is empty. Symlinks, nonregular files, duplicate/unknown/missing fields, oversized documents (>16384 bytes), expired receipts and mismatched bindings fail closed. Do not expose or write this file through speech, model output or public APIs. Keep it under operator-only write permissions; the setting is redacted from public diagnostics.

The exact root keys are `generator` and `validator`; each contains every `StoryContextReceipt` field: `base_url`, `model`, `model_digest`, `server_version`, `context_ceiling`, `template_reserve`, `expires_at`, `runner`, `tokenizer_contract`, `truncate_false_verified`, `shift_false_verified`. Use `runner="llamacpp"` and `tokenizer_contract="utf8_byte_budget_v1"` (resource estimation only). `expires_at` is an operator-selected Unix timestamp, not automatically renewed. Select each model's independently accepted context ceiling and a resource reserve; do not copy the generator capacity blindly to the mini model. Confirm exact version/tag/runner/digest and no-truncation protocol trace before marking the two verified flags true. No deployable acceptance file is bundled.

Actual `BoundedConversationEngine` construction loads and binds both contracts. Existing startup/controlled warmup refreshes them with metadata-only GETs after ordinary warmup. This adds no inference, polling, or new HTTP endpoint. Ordinary warmup itself already performs its existing inference probes; a trusted operator can instead call `refresh_story_contracts(engine)` for metadata-only refresh. If either required model is unloaded, admission remains false until loaded by independently authorized existing operations and refreshed. Editing the receipt requires rebuilding/restarting the application; expiry and observed changes invalidate it during operation.
