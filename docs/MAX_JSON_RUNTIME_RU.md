# JSON-профиль от клиента Макса

RFID, ключ метки, HTTPS и поиск карточки принадлежат клиенту Макса.
MISHKA получает готовую карточку через его Python-интерфейс. Собственного
считывателя или поиска профиля по UID в MISHKA нет.

## Обычный запуск с тестовой базой

Используется привычный `./start.sh` и штатный сервер приложения.
Для подключения настоящего считывателя и телефонной платы с вымышленными
карточками задайте в локальном конфиге:

```dotenv
MISHKA_PROFILE=local_gpu
MISHKA_RUNTIME_MODE=exhibition
MISHKA_HARDWARE_MODE=physical
MISHKA_IDENTITY_MODE=max_json
MISHKA_MAX_CLIENT_SOURCE=local_demo
MISHKA_MAX_SYNTHETIC_DATA=true
MISHKA_ALLOW_DEGRADED_HARDWARE=false
MISHKA_ALLOW_QUERY_TOKEN=false
MISHKA_MAX_CLIENT_BUNDLE=/absolute/path/phone-ubuntu-client-local-demo.zip
MISHKA_MAX_DEMO_STATE=/absolute/path/existing-demo-state
MISHKA_MAX_DEMO_PORT=19443
```

Пакет Макса и состояние demo не входят в Git. Состояние должно быть заранее
создано штатным `init` этого пакета; запуск MISHKA не создаёт новые сертификаты,
не сбрасывает базу и не регистрирует браслеты. Не направляйте эти параметры
на реальные медицинские данные.

Настройки моделей, аудио, Arduino HID и последовательного порта остаются
обычными настройками MISHKA. До готовности штатного runtime взаимодействие
закрыто. Отдельного флага, принудительно объявляющего сервер готовым,
в обычном запуске нет. Остановка: Ctrl+C.

`/ready` показывает готовность приложения отдельно от готовности профиля.
Для `local_demo` production_ready всегда false: реальные устройства и модели
не превращают вымышленную базу в принятую рабочую интеграцию.

## Сертификаты и права

Локальный demo использует сертификаты, созданные механизмом из переданного
пакета Макса для localhost. Это не сертификаты его внешнего API.
Проверка CA и имени сервера не отключается. Публичный CA внешнего сервера
сам по себе не даёт доступ к нему.

Внешний API в этом варианте запуска не включён. Для него отдельно нужны
доступный адрес с подходящим именем в сертификате, разрешённое provisioning,
действующий пропуск установки и согласованное защищённое хранение.
Перенос Windows DPAPI-файлов в Linux не заменяет эту настройку.

Пользователю сервиса нужны права только на конкретные Z-2 и Arduino.
Не запускайте всё приложение от root и не давайте ему доступ ко всем
клавиатурам через группу input. Один считыватель обслуживает один процесс.

## Карточка и завершение сеанса

При новом сканировании прежний профиль сбрасывается. Неизвестная или
неактивная метка не даёт персонализацию. Писк считывателя подтверждает чтение,
а не успешную авторизацию. При возврате трубки собственный контекст MISHKA
и состояние клиента очищаются. Сохраняются также сроки действия исходного
клиента и серверной карточки.

Demo-привязки действуют на операционный день. Продление выполняется явно
штатной командой `renew-day` пакета Макса; MISHKA не продлевает их сама.
Быстрый повторный скан не должен продлевать срок карточки.

У исходного клиента нет постоянного сетевого heartbeat: сетевой отказ
может обнаружиться только при следующем запросе. Это не обещание мгновенной
проверки соединения.

UID, карточки, имена, диагнозы, пропуска и ключи не должны попадать в логи,
репозиторий или диагностические ответы. Для проверки нужны только коды
результатов и состояния.

## Программные тесты без оборудования

Старый `scripts/run_max_json_demo.py` остаётся отдельным синтетическим
инструментом. Его команды имитируют метки и трубку; он не заменяет обычный
запуск и не подтверждает работу звука или физических устройств.


Контрактные тесты JSON и runtime запуска не требуют пакета Макса:

```bash
.venv/bin/python -m pytest tests/test_max_client_runtime.py tests/test_json_only_contract.py -q
```

Для двух E2E-модулей с настоящими HTTPS/SQLite передайте отдельно полученный
неизменённый ZIP (или абсолютный путь к каталогу его исходников):

```bash
MISHKA_TEST_MAX_BUNDLE=/absolute/path/phone-ubuntu-client-local-demo.zip \
  .venv/bin/python -m pytest tests/test_max_json_integration.py tests/test_max_json_stand.py -q
```

Вместо переменной можно добавить каталог исходников или ZIP в `PYTHONPATH`.
Без пакета пропускаются только эти внешние E2E-модули. Ошибочный явно заданный
путь, отсутствующие зависимости или ошибки внутри установленного пакета
считаются ошибками, а не пропуском. Тесты создают временную вымышленную базу
и TLS-материалы; рабочая база и оборудование не используются.
