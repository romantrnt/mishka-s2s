# MISHKA

Детский телефон и веб-панель: разговор, игры, проверенные записи сказок,
авторские истории, свет и кнопочное управление. Основной рабочий код находится
в `app/foundation`; сценарий — `app/scenarios/canonical_graph.py`.

## Текущая эксплуатация

Канонический подготовленный каталог сервера — `/home/server/mishka`
(WSL Ubuntu-24.04, пользователь `server`). Его SHA должен совпадать с опубликованным
`origin/main`. Подготовленный каталог не означает, что процесс на него переключён.
На 25 ноября переключение работающего стенда `98eb560` на порту `18024`
запрещено Романом до отдельного решения. Не перезапускайте его даже в простое.
Точный статус и подготовленные команды хранятся в Obsidian:
`Mishka/Antigravity/demo-checkpoint-20261124/main-polish-20261125/`.

Рабочий голос — VoxCPM2 `555`, RVC выключен; Whisper `large-v3-turbo`,
LLM `qwen3:14b`. Модель, adapter, reference и их манифест берутся из закрытого
профиля оператора. Не подставляйте другую модель или fallback ради успешного запуска.
Числа, единицы, сокращения и консервативное восстановление ё уже поддерживаются.
Свежая акустическая проверка «Рад тебя видеть» и «Тебя давно не видел» ещё открыта;
текстовый тест не доказывает сохранность согласного в звуке.

## Установка и конфигурация

Нужен Python 3.12 и зависимости из `requirements.txt`; для JSON-demo см.
[отдельный runbook](docs/MAX_JSON_RUNBOOK_RU.md). Весов моделей и секретов в Git нет.
`.env.example` — публичный шаблон, а не готовая аппаратная конфигурация.
Полный рабочий `.env` восстанавливается оператором из действующего приватного
профиля, сохраняется с правами `600` и не публикуется. Сохраняйте исходный профиль
и данные перед обновлением. В WSL пути устройств и проброс USB проверяются отдельно.

Приложение запускается через `scripts/run_stand.py`, который читает `.env`
или `MISHKA_ENV_FILE`. Переменные процесса имеют приоритет. Для гаражного профиля
также нужны прежние пути CUDA-библиотек и дополнительных Python-зависимостей:
проверенная команда подготавливается вместе с закрытым профилем.
Не используйте `start.sh --help` для проверки: этот старый launcher меняет ALSA
и усиление микрофона до запуска. `bash -n start.sh` безопасно проверяет только синтаксис.

## Логи и защита

Оперативные технические логи: `MISHKA_LOG_LEVEL=info`,
`MISHKA_DIAGNOSTICS_LEVEL=standard`. По умолчанию `NO_VOICE_RECORDING=true`,
`DIALOGUE_JOURNAL_ENABLED=false`. Private journal не нужен для технических логов
и не должен включаться вместе с verbose. Хранение/ротация stdout задаются
менеджером процесса; приложение не объявляет несуществующую ротацию включённой.

Отдельного прежнего quality-validator флага сейчас нет: качество речи,
обязательная output safety и контекстные действия используют общий gate.
`VALIDATION_PROVIDER=ollama` и `VALIDATION_FAIL_CLOSED=1` сохраняются.
Отключать этот gate или `spoken_requirement` ради снятия quality-check нельзя.
Safety, ownership, urgent/help и capability checks остаются обязательными.

## Разработка и проверки

Сначала прочитайте [AGENTS.md](AGENTS.md). Работайте в ветке `ag/mishka-*`;
`main` обновляется без переписывания истории только по явному поручению Романа.
Не удаляйте ветки, полезные ресурсы, старые рабочие данные или внешний код Макса.
Публичные записи имён в `assets/names` — используемый ресурс, не временные файлы.
Исторические аудиты в `docs/qa` и эксперименты в `experiments` не включают
эксперимент автоматически в рабочий голос.

Локальные проверки выполняются из корня через `.venv/bin/python -m pytest`.
Для выбранного сценария указывайте соответствующие файлы из `tests`;
модельные/аппаратные проверки требуют отдельного изолированного окружения.
Не загружайте вторую модель на GPU работающего стенда и не используйте его
устройства для подготовки. [Последние полевые исправления](docs/qa/field-feedback-20261125.md)
разделяют source tests, тестовые провайдеры и непроверенную акустику.
